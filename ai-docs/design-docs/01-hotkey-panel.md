# 快捷键面板与交互设计

## 1. 目标

Hotkey 是一个在手机上快速触发电脑快捷键的 Synra 插件。用户打开插件后可以直接看到一组常用系统快捷键，点击一个方块即可让已连接的电脑执行对应组合键。

第一阶段只提供系统基础快捷键。后续可以沿用同一套方块模型扩展 Photoshop、Premiere Pro 等应用快捷键，但本阶段不加入应用分类和自定义快捷键编辑能力。

## 2. 页面结构

插件打开后直接显示快捷键面板：

```text
┌─────────────────────────────┐
│ 热键                 编辑  ⋮ │
├─────────────────────────────┤
│  [图标]  [图标]  [图标]      │
│   复制     剪切     粘贴     │
│  Ctrl C   Ctrl X   Ctrl V   │
│                             │
│  [图标]  [图标]  [图标]      │
│   撤销     重做     全选     │
│  Ctrl Z   Ctrl Y   Ctrl A   │
│                             │
│             …               │
└─────────────────────────────┘
```

页面只保留与当前任务直接相关的控件：

- 顶部标题：显示“热键”。
- 编辑入口：进入位置编辑模式。
- 列数入口：在普通模式或编辑模式中都可以调整 3、4、5 列。
- 快捷键网格：占据主要页面空间，纵向内容不足时自然滚动。

不增加单独的“开始使用”页，也不要求用户先进入设置页面才能触发快捷键。

## 3. 快捷键方块

每个快捷键使用一个正方形按钮表示，内容固定为三层：

1. 上方图标：表达动作或系统功能。
2. 中间主标题：使用大号、醒目的中文动作名称，例如“复制”“剪切”“粘贴”“打开文件夹”。
3. 下方副标题：使用较小、低对比度的灰色快捷键组合，例如 `Ctrl C`、`Ctrl X`、`Ctrl V`、`Win E`。

主标题是方块的主要识别信息，快捷键组合是辅助信息。用户首先通过中文动作理解功能，再通过灰色小字确认实际按键，不让英文组合抢占视觉重点。

### 文字层级

- 中文动作名称使用较大的字号和较高的文字对比度。
- 快捷键组合使用较小字号、灰色文字和较弱对比度。
- 快捷键组合不使用与主标题相同的字重，不应成为方块的第一视觉焦点。
- 中文动作名称和快捷键组合各占一行；必要时允许中文名称在有限宽度内换行，但应优先通过简短名称避免换行。
- 图标、中文名称和快捷键组合在方块内垂直居中排列，并保留稳定的上下间距。

方块的定义由插件内置。当前版本中用户不能：

- 修改快捷键组合；
- 新增自定义快捷键；
- 删除内置快捷键；
- 修改快捷键对应的图标和名称。

用户只能调整方块顺序，以及选择一行显示 3、4 或 5 个方块。

## 4. 普通模式

普通模式是插件打开后的默认模式，也是主要使用模式。

### 点击行为

- 点击快捷键方块，立即向当前目标电脑发送对应的固定组合键。
- 点击只触发一次完整组合键，不需要在手机上持续按住。
- 点击后保留短暂的按下反馈，让用户确认操作已经被触发。

### 按下反馈

按下反馈至少包含以下变化：

- 方块轻微缩小或下沉，形成明确的按压感；
- 背景色或边框色短暂变化；
- 松开后恢复普通状态。

反馈只表达“本次点击已被接收”。电脑端执行结果、连接异常等状态另行使用统一的状态提示表达，不改变快捷键方块的固定定义。

## 5. 编辑模式

点击顶部“编辑”后进入编辑模式。编辑模式用于整理方块顺序，避免普通点击时误触发快捷键。

### 编辑模式行为

- 方块显示可拖拽的视觉提示，例如拖拽手柄、悬浮阴影或轻微抬升效果。
- 用户按住并拖拽方块，可以把它移动到其他位置。
- 拖拽过程中，其他方块为目标位置让出空间，并保持网格布局。
- 编辑模式下点击方块不发送快捷键。
- 点击“完成”或返回普通模式后，当前顺序立即保存。

### 可编辑范围

本阶段只允许调整位置。快捷键的组合、图标、显示文本和内置身份不可编辑，也不提供“添加快捷键”入口。

### 拖拽与滚动

- 网格内容较长时，拖拽可以跨越多个可见行。
- 拖拽到屏幕顶部或底部附近时，页面自动进行纵向滚动。
- 横向不产生独立滚动区域，避免与列布局产生冲突。

## 6. 列数与网格布局

用户可以选择每行显示 3、4 或 5 列。切换列数只改变布局，不改变快捷键定义和当前排列顺序。

### 布局规则

网格必须满足以下规则：

- 所有快捷键方块宽高相等；
- 方块始终保持正方形；
- 同一行的方块宽度一致；
- 网格左右边距与方块之间的横向 gap 相等；
- 第一列贴近左侧边距，最后一列贴近右侧边距；
- 不同列数下自动重新计算方块尺寸和间距；
- 不出现横向滚动条。

可以用下面的关系描述一行的宽度：

```text
可用宽度 = 左边距 + n × 方块宽度 + (n - 1) × gap + 右边距
左边距 = 右边距 = gap
```

其中 `n` 是当前列数。实际实现应根据屏幕可用宽度、安全区和最小触控尺寸计算方块宽度，并让 `gap` 随列数和屏幕宽度自动调整：

- 3 列：方块较大，间距可以相对宽松；
- 4 列：在方块尺寸和间距之间取平衡；
- 5 列：方块较小，间距相对收紧。

方块高度直接等于计算出的方块宽度，不单独设置固定高度。

### 响应式与安全区

- 使用屏幕实际可用宽度，不覆盖刘海、圆角和底部手势区域。
- 屏幕旋转或窗口尺寸变化时重新计算网格。
- 在窄屏幕上优先保证方块仍满足可触控尺寸；如果无法同时满足，应优先保持布局可用，并在评审时确定最小尺寸策略。

### 内容滚动

- 内容超过可视高度时，页面使用纵向滚动。
- 滚动只影响快捷键列表区域，顶部标题和编辑入口保持可用。
- 系统基础快捷键数量较少时，页面不强行填满高度。
- 快捷键方块不被压缩成非正方形，也不通过缩小文字来消除纵向滚动。

## 7. 初始内容范围

第一阶段提供系统基础快捷键，优先覆盖高频、低认知成本的操作。方块的中文主标题和快捷键副标题例如：

- `复制` / `Ctrl C`
- `剪切` / `Ctrl X`
- `粘贴` / `Ctrl V`
- `撤销` / `Ctrl Z`
- `重做` / `Ctrl Y`
- `全选` / `Ctrl A`
- `保存` / `Ctrl S`
- `查找` / `Ctrl F`
- `打开文件夹` / `Win E`

具体列表、排序和图标在设计确认阶段单独确定；这些内容属于内置配置，不属于用户编辑能力。

## 8. 配置保存

建议将以下设置保存为手机端的插件偏好：

- 当前列数；
- 快捷键方块顺序。

首次打开使用默认列数和默认顺序。保存的是面板显示偏好，不改变快捷键的定义，也不需要用户为每个电脑重复配置。

## 9. 状态与异常反馈

快捷键方块需要至少支持以下可见状态：

- 默认：可点击并显示固定快捷键；
- 按下：显示短暂的按压反馈；
- 不可用：当前没有可发送的目标电脑时，阻止误触并给出原因；
- 发送失败：保留方块位置和定义，通过轻量提示告知失败原因。

异常提示不应把用户带离快捷键列表，也不应破坏当前滚动位置和编辑顺序。

## 10. 验收标准

设计进入开发前，应满足以下可验证条件：

1. 打开插件后第一屏就是快捷键列表。
2. 每个快捷键都以“上图标、中文主标题、灰色快捷键副标题”的正方形方块展示。
3. 点击方块有清晰的按下效果，并触发固定组合键。
4. 进入编辑模式后可以拖拽调整顺序，编辑模式点击方块不会发送快捷键。
5. 用户不能修改组合键，也不能新增自定义快捷键。
6. 3、4、5 列均能自动适配屏幕宽度，方块保持正方形。
7. 左右边距与横向 gap 一致，列数变化时间距自动调整。
8. 快捷键数量较多时可以纵向滚动，不能出现横向滚动。
9. 切换列数和调整顺序后，退出并重新打开仍能恢复用户的面板偏好。

## 11. 待评审问题

以下问题不阻塞当前页面方案，但需要在设计确认前定稿：

- 顶部列数入口使用文字选择器、图标菜单还是分段控件；
- 编辑模式的进入、完成按钮具体放在顶部何处；
- 初始快捷键的完整列表、排序和图标；
- 没有当前目标电脑时的提示方式；
- 最小触控尺寸和不同屏幕宽度下的 gap 数值范围。
